# Luni Arena 0.1.21 — kit para preparar o release

Este ZIP contém o projeto Android completo, os núcleos ARM64 compilados de revisões identificadas, seus hashes e o código-fonte correspondente em `third_party/`. **Ainda não contém um AAB assinado nem está liberado para venda.** A trava de release permanece ativa até que a fonte completa desta versão esteja publicada numa URL HTTPS sua. Também falta sua revisão das licenças e o teste do pacote distribuído pela Play.

## O que já está pronto

- Aplicativo `app.luni.arena`, `versionCode 23`, `versionName 0.1.21`, baseado na versão 0.1.20 da biblioteca incremental.
- Os dois `.so` ARM64 ficam em `app/src/main/jniLibs/arm64-v8a`; `release-cores.properties` registra os hashes SHA-256 e commits reais; o código exato dos núcleos fica em `third_party/`. Veja `docs/NUCLEOS_RELEASE.md`.
- `tools/release_preflight.py` lista as pendências técnicas sem trocar ou baixar os binários. O projeto não inclui ROMs, BIOS, saves, chaves de assinatura ou credenciais.

## Seu caminho no Windows

1. Extraia o ZIP em `D:\LuniArena\luni-arena`, fora do OneDrive. Abra **essa pasta `luni-arena`**, a que contém `settings.gradle`, no Android Studio. Em **File → Settings → Languages & Frameworks → Android SDK**, confirme Android Platform 36, Build Tools 35.0.0 e 36.0.0, NDK 27.2.12479018 e CMake 3.22.1. Use o JDK 17 do Android Studio.
2. Faça uma cópia de segurança do projeto. Tenha uma conta GitHub e escolha um nome novo para o repositório, por exemplo `luni-arena`; **não crie o repositório pelo site ainda**. Anote `SEU_USUARIO` e o nome escolhido. A fonte a publicar precisa incluir `app/src/main/java`, `app/src/main/cpp`, `third_party`, `COPYING`, Gradle, manifesto, docs e os comandos em `docs/NUCLEOS_RELEASE.md`. Não publique `*.jks`, `local.properties`, senhas, ROMs nem dados de usuário. O `.gitignore` já exclui chaves, caches e os binários `.so`; publicar fonte sem binários é esperado, desde que o build dos núcleos esteja documentado. Mantenha o repositório e esta revisão acessíveis enquanto distribuir o app.
3. No arquivo `app\src\main\assets\SOURCE_URL.txt`, apague `PRE_PUBLICATION_SETUP_REQUIRED` e cole **só** `https://github.com/SEU_USUARIO/NOME_DO_REPOSITORIO/tree/v0.1.21`, trocando os dois nomes pelos seus. Com **GitHub Desktop**, use **File → Add local repository → Choose** e selecione `D:\LuniArena\luni-arena`; se oferecer criar um repositório Git nessa pasta, aceite. Faça **Commit to main** e **Publish repository**, informando o nome escolhido e deixando desmarcado **Keep this code private**. No GitHub, abra **Releases → Draft a new release**, crie a tag `v0.1.21` na revisão que contém esse arquivo e publique a release da fonte. Abra a URL do arquivo em janela anônima e verifique que mostra o código e `third_party`. A tag apontará para a revisão exata e evita URL autorreferente por hash de commit.
4. No terminal do Android Studio, na raiz `D:\LuniArena\luni-arena`, execute `py -3 tools\release_preflight.py` e `py -3 tools\verify_release_cores.py`. Ambos precisam passar sem erro. **Não execute `tools/fetch_core.py` nem apague os `.so` incluídos:** isso trocaria os binários por nightlies.
5. Preencha seu nome e e-mail em `docs\POLITICA_PRIVACIDADE_PARA_SITE.html` e publique a política em HTTPS. Revise as licenças de todos os componentes, especialmente a compatibilidade GPLv3/ML Kit Translation e a procedência dos cheats; confira a atribuição de tradução e a declaração de dados. Se não puder resolver esses pontos, **pare antes de enviar para venda**. Não use imagens ou nomes de jogos na ficha sem os direitos de divulgação. Veja `LICENCA_E_FONTES.md` e `docs/GUIA_PUBLICACAO_PLAY.md`.
6. No Android Studio use **Build → Generate Signed Bundle / APK → Android App Bundle → Next**. Selecione **Create new** para gerar sua chave de upload `.jks` no PC ou **Choose existing** se já tiver a chave certa. Preencha alias e senhas, escolha **release**, finalize. Não envie a chave nem senhas a ninguém. O AAB deverá aparecer em `app\release\` ou `app\build\outputs\bundle\release\`; use **Locate** na notificação do Android Studio. No terminal, execute `py -3 tools\check_bundle_native.py CAMINHO_DO_AAB` com o caminho encontrado; o script deve listar todos os núcleos e a URL real. Guarde também `app\build\outputs\mapping\release\mapping.txt`.
7. Envie o AAB primeiro a **Teste interno** na Play Console. Instale pelo link da Play em celular e tablet, teste jogos solo e online local, ambos os núcleos, controle Bluetooth/USB, áudio, cheats, saves e orientação. Se havia APK debug instalado, **exporte seus saves antes de desinstalar**: a assinatura de teste pode ser incompatível com a versão Play. Depois siga as tarefas da Play Console e o roteiro completo em `docs/GUIA_PUBLICACAO_PLAY.md`.

**Importante:** a GPL permite cobrar pela distribuição, mas os destinatários conservam os direitos de obter, modificar e redistribuir o código coberto. A chave de assinatura precisa permanecer somente com você. Esta entrega não promete impedir pirataria nem garante aprovação da loja. O binário aqui foi verificado estaticamente; o teste real via Play ainda é necessário.
